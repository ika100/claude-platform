# gitops plugin

Agents and commands for the GitOps repository — the single repo that wires service repos into one or more Kubernetes clusters via ArgoCD.

## Agents

| Agent | Model | Purpose |
|---|---|---|
| `deployment` | sonnet | Maintains the ApplicationSet, cluster-wide add-ons, and per-service overrides |
| `promote` | sonnet | Pins image tags + kustomize refs when promoting a service across environments |

## Commands

| Command | Purpose |
|---|---|
| `/gitops:promote <service> <from> <to> [version]` | Opens a PR pinning `<service>` to `<version>` in the `<to>` overlay |

## Conventions enforced

- Service repos opt in to GitOps discovery via the GitHub topic `deployable-service`.
- Every service repo has `k8s/overlays/prod/kustomization.yaml`.
- One Argo `Application` per service, namespace == repo name.
- Cluster add-ons live in `apps/<name>.yaml`; service applications are generated by the `ApplicationSet` in `apps/applicationset-services.yaml`.

## Dependencies

Pairs with the `shared` plugin for quality + security checks on infra YAML. Enable both:

```json
{
  "enabledPlugins": {
    "gitops@ika100-claude": true,
    "shared@ika100-claude": true
  }
}
```

## What this plugin does NOT do

- It does not edit service-repo manifests. Open a PR in the service repo.
- It does not `kubectl apply` directly. Argo owns reconciliation.
- It does not auto-merge promotion PRs. Promotions are intentional — humans approve.
